Entry Point Main.java

The very first file Java runs when you start the application. Sets up the database and hands off to the Login screen.

What this file does: Starts the application on the correct GUI thread, initialises the database, and opens the Login window.
Concept
package
Like a folder name. Groups related files so Java knows where to find them.
Concept
import
Brings in code that lives elsewhere so you don't have to rewrite it.
Concept
public static void main
The special method Java looks for first — the starting line of every Java program.
Concept
SwingUtilities.invokeLater
Safely hands GUI work to the Event Dispatch Thread before any window appears.

Data Model Product.java

A blueprint describing what a "Product" is. Every product in the system is an object made from this template.

What this file does: Defines a Product as six immutable fields — ID, name, category, price, quantity, and image filename — plus getter methods to read them safely.
Concept
class
A blueprint. Create as many Product objects as you like from this one definition.
Concept
private final
private: only this class can touch the field. final: locked after the constructor sets it — never changes.
Concept
constructor overloading
Two constructors with different parameter lists. The 5-param one is for new products (no ID yet); the 6-param one is for products loaded from the database.
Concept
getter methods
Small methods like getName() that safely expose private fields to other classes.

Data Model CartItem.java

A small wrapper that pairs a Product with a chosen quantity. Used to represent one line in a customer's shopping cart.

What this file does: Holds a reference to a Product and the number of units the customer wants to buy. The cart in ClientDashboardForm is a Map<Integer, CartItem> — each product's ID maps to one CartItem.
Concept
composition
CartItem has-a Product rather than extending it. This is the preferred way to combine behaviour in Java — favour composition over inheritance.
Concept
immutable object
Both fields are private final. To change a cart quantity the app creates a new CartItem rather than mutating the old one — simpler and safer.
Concept
getProduct()
Returns the full Product object stored inside. Other code calls this to read the name, price, image, etc. without knowing the internal structure of CartItem.
Concept
getQuantity()
Returns how many of this product the customer wants. Multiplied by the product price in the checkout to calculate the line total.

Database Layer DatabaseManager.java

The single file that talks directly to SQLite. Everything else goes through this class to read or write data.

What this file does: Creates tables and seed data on first launch, provides a Singleton connection manager, authenticates users (now including a client_user account), and handles all CRUD operations for products.
Pattern
Singleton
Guarantees only one DatabaseManager ever exists, so the whole app shares one managed connection point.
Concept
PreparedStatement
Parameterised SQL — values go in as ? slots, never as raw text. Prevents SQL injection attacks.
Concept
try-with-resources
Auto-closes connections and statements when the block ends — even if an exception is thrown. No resource leaks.
New
Dual default users
Now seeds both an admin and a client_user account so both roles can be tested out of the box.

UI — Login LoginForm.java

The first screen the user sees. Now routes to two different dashboards depending on who logs in.

What this file does: Draws the login card, validates credentials, then opens DashboardForm for the admin account or ClientDashboardForm for any other account. Role-based routing happens entirely inside the login() method.
New
Role-based routing
After authentication, an if/else check on the username decides which dashboard to open. "admin" → inventory dashboard; anything else → client shopping dashboard.
Concept
extends JFrame
LoginForm inherits all window behaviour from JFrame for free — title bar, close button, sizing.
Concept
FocusListener
Detects when a text field gains or loses focus — used to show/hide grey placeholder text.
Concept
dispose()
Destroys the login window after a successful login so it doesn't sit in memory behind the new dashboard.

UI — Admin Dashboard DashboardForm.java

The admin's inventory management window. Shown only to the admin account after login.

What this file does: Displays all products in a scrollable card grid. Provides Add, Edit, Delete, Search, and Refresh controls. Includes a Logout button that returns to the Login screen. Only the admin sees this view.
Concept
BorderLayout
Divides the window into NORTH (header), SOUTH (controls), and CENTER (product grid) zones.
Concept
FlowLayout
Arranges product cards left-to-right, wrapping to the next row when the line fills — like words in a paragraph.
New
Logout button
Calls dispose() on the dashboard and opens a fresh LoginForm — letting a different user sign in without restarting the app.
Concept
JDialog
Modal sub-window used for Add/Edit product forms. Blocks interaction with the dashboard until closed.

UI — Client Dashboard ClientDashboardForm.java

The shopping interface for non-admin users. Customers browse products, add them to a cart, and proceed to checkout.

What this file does: Shows a product grid with an "Add to Cart" button on each card. Maintains an in-memory cart (Map<Integer, CartItem>), updates the cart button counter, enforces stock limits, and opens the CheckoutDialog when the customer is ready to pay. After payment it deducts stock from the database.
New
Shopping cart
A LinkedHashMap<Integer, CartItem> keyed by product ID. LinkedHashMap preserves insertion order so items appear in the cart in the order they were added.
New
Stock enforcement
Before adding to the cart, the code re-fetches the product from the database to get the live stock count — preventing customers from adding more than what's available.
New
completePurchase()
Called by CheckoutDialog on payment. Loops through cart items and calls updateProduct() to reduce each product's stock in the database, then clears the cart.
Concept
Runnable callback
A Runnable is passed into CheckoutDialog. When payment succeeds, the dialog calls onPaymentComplete.run() — triggering completePurchase() back in this class without the dialog needing to know about it directly.

UI — Checkout CheckoutDialog.java

A three-step modal dialog that guides the customer through Cart review → Shipping details → Payment. The most complex UI component in the project.

What this file does: Uses a CardLayout to host three panels in one dialog and a step index to track which panel is visible. Validates each step before advancing. On the final step it calls the onPaymentComplete callback to trigger stock deduction and cart clearing in the parent window.
New
CardLayout (multi-step)
All three step panels live in the same container; CardLayout shows only one at a time. Switching steps is just show(cards, stateName) — no panels are created or destroyed mid-flow.
New
enum CardState
An enum is a fixed list of named constants. CardState.CART, SHIPPING, and PAYMENT make the step logic readable and type-safe — impossible to accidentally pass an invalid step name.
New
Order summary panel
The Cart Review step shows each CartItem with its thumbnail, quantity controls, and a running total. The summary column shows subtotal + shipping + 8% tax.
New
Custom card icons
createCardIcon() paints mini payment-brand badges (Visa, Mastercard, Verve) using Graphics2D.fillRoundRect and centred text — no images needed.

Build & Run run.sh

A Bash script that launches the compiled JAR. Run ./run.sh instead of typing the full java command each time.

What this file does: Checks the JAR exists, prints a helpful build reminder if it doesn't, then executes it — forwarding any extra arguments.
Concept
shebang (#!)
First line of any shell script. Tells the OS which interpreter to use — here Bash, located via /usr/bin/env for portability.
Concept
set -euo pipefail
Three safety flags: exit on error (-e), treat unset variables as errors (-u), catch pipeline failures (-o pipefail).
Concept
[ ! -f "$VAR" ]
File-existence test. True when the file is missing. Guards against running a non-existent JAR.
Concept
"$@"
Forwards all arguments passed to run.sh straight through to java — useful for future flags.
