Entry Point Main.java

This is the very first file Java runs when you start the application. Think of it as the "on" switch — it sets everything else in motion.

What this file does: It starts the application in the correct way for a graphical program, prepares the database, and shows the Login screen to the user.
Concept
package
Like a folder name. Groups related files together so Java knows where to find them.
Concept
import
Tells Java "I want to use code that already exists elsewhere." You import it so you don't have to write it from scratch.
Concept
public static void main
The special method Java looks for first. Every Java program must have exactly one — it's the starting line of the race.
Concept
SwingUtilities.invokeLater
GUI programs need to be started on a special thread. This method safely hands control to that thread before showing any windows.

Data Model Product.java

A blueprint that describes what a "Product" is in this application. Whenever the app needs to work with a product, it creates an object from this blueprint.

What this file does: Defines a Product as a bundle of six pieces of information — ID, name, category, price, quantity, and image. Also provides "getter" methods so other parts of the code can safely read those values.
Concept
class
A blueprint or template. You can create as many Product objects as you like from this one class — like stamping coins from a single mould.
Concept
private final
private means only this class can see the variable. final means once set, the value never changes — it's locked.
Concept
constructor
A special method with the same name as the class. It runs once when you create a new object, filling in all the initial values.
Concept
getter method
A small method whose only job is to return one private value. e.g. getName() returns the product's name.

Database Layer DatabaseManager.java

The only file that talks directly to the SQLite database. All other files go through this one whenever they need to save, update, delete, or fetch data.

What this file does: Creates and manages the database file, provides a single shared instance of itself (Singleton pattern), and contains one method for every database action: init, check credentials, add/update/delete products, and search.
Pattern
Singleton
A design rule that says "only one copy of this object may exist at a time." Used here so the whole app shares one database connection manager.
Concept
PreparedStatement
A safe way to run SQL queries. Values are inserted as parameters, not as raw text — this prevents hackers from injecting malicious SQL.
Concept
try-with-resources
The try (Connection conn = …) syntax automatically closes the connection when done, even if an error occurs — preventing memory leaks.
Concept
ResultSet
The rows returned from a SELECT query. You call rs.next() to move to the next row, and rs.getString() etc. to read each column.

UI — Login LoginForm.java

Builds and displays the Login window — the first screen the user sees. Handles drawing the UI components and validating credentials when the Login button is clicked.

What this file does: Creates the window frame, draws a white rounded card, lays out the email field, password field, and login button, and wires up the login action that checks credentials against the database.
Concept
extends JFrame
LoginForm inherits from JFrame — it gets all the window behaviour (title bar, close button, size) for free just by extending it.
Concept
paintComponent
Override this to draw custom graphics. Here it's used to draw rounded rectangles for the card and the button instead of default square shapes.
Concept
FocusListener
Detects when a text field gains or loses focus. Used here to show/hide placeholder text — the grey hint that disappears when you click the field.
Concept
ActionListener (lambda)
e -> login() is a lambda — a short way to say "when this button is clicked, call the login() method."

UI — Dashboard DashboardForm.java

The main application window after login. Displays product cards in a scrollable grid and handles all product management actions: add, edit, delete, search, and refresh.

What this file does: Builds a header bar, control bar, and scrollable product grid. Fetches products from the database and renders each one as a card. Opens modal dialogs for adding and editing products.
Concept
BorderLayout
Divides a panel into five zones: NORTH, SOUTH, EAST, WEST, CENTER. Used to place the header at top, control bar at bottom, and products in the middle.
Concept
FlowLayout
Arranges children left-to-right and wraps to the next row when the line is full — like words in a paragraph. Used for the product card grid.
Concept
JScrollPane
Wraps another panel and adds scroll bars automatically when the content is taller than the visible area.
Concept
JDialog
A smaller modal window that appears on top of the main window. Used for the "Add Product" and "Edit Product" forms. The user must close it before returning to the dashboard.

Build & Run run.sh

A Bash shell script that launches the compiled application. Instead of typing the full java -jar … command each time, you just run ./run.sh.

What this file does: Checks that the compiled JAR file exists before trying to run it, prints a helpful error message if it doesn't (and reminds you to build first), then executes the JAR, forwarding any extra command-line arguments.
Concept
shebang (#!)
The very first line of any shell script. Tells the operating system which interpreter to use — here /usr/bin/env bash finds Bash wherever it's installed on the machine.
Concept
set -euo pipefail
Three safety flags in one: -e exits on any error, -u treats unset variables as errors, -o pipefail catches failures in piped commands. Together they prevent silent failures.
Concept
[ ! -f "$VAR" ]
A file-existence check. -f is true if the path is a regular file. The ! negates it — so the block runs when the file is missing.
Concept
"$@"
Passes all arguments the user gave to run.sh straight through to java -jar. Useful for future flags without changing the script.
